# 画面の寸法（Figma とコード）

Figma「家計簿」（`k99TXVIrWbQ9YYSNBnbaFW`）の画面のデザインと、アプリの画面が、画面の幅ごとに一致しているかを確かめる。正は Figma。

## Figma の画面の置き方

- 機能ごとにページを分ける：`画面 / HOME`・`画面 / 支出`・`画面 / 支出属性`・`画面 / 収入`・`画面 / 収入属性`・`画面 / 年間レポート`・`画面 / 共通の状態`。
- ページの中は、状態ごとにセクションを作る（通常・読み込み中・エラー・保存後・削除確認など）。セクションの名前が状態の名前。
- セクションの中は、左から 1920・1440・1024・390 の幅の画面を並べる。セクションの内側の余白は上下左右とも 120 で、画面の間と同じ。セクションの間は 200（余白が狭いと、縮小して見たときにセクションの見出しと画面の名前が切れる）。画面の名前は「状態 / 幅×高さ」で、幅×高さは想定する端末の画面の大きさ（1920×1080・1440×900・1024×768・390×844）を書く（例：`支出一覧（読み込み中） / 1024×768`）。
- ある幅にしかない状態は、その幅だけを置く（`（メニューを開いた状態）` は 1024 と 390、`（下までスクロールした状態）`・`（操作メニューを開いた状態）` は 390 だけ、`（サイドメニューを隠した状態）` は 1920 と 1440 だけ。1024 はサイドバーをたたんだ状態が通常で、メニューを開くと本文に重ねて出す）。
- 画面の高さは端末の画面の高さにする（1920 は 1080、1440 は 900）。1920 と 1440 は本文の中がスクロールするので、端末の画面に見える範囲を描く。年間レポートと HOME の一部は、全体が見えるよう中身の高さにしている。1024 と 390 はページ全体がスクロールするので、端末の画面の高さ（768・844）以上で、中身に合わせて伸ばす（下までスクロールした状態とメニューを開いた状態は端末の高さ）。名前の幅×高さは、高さを伸ばした画面でも端末の大きさのまま。

## 書き出す寸法

中身のデータや文字の形に左右されないものだけにする（見本のデータとアプリのデータは違うため）。

- サイドバーがあるか、ある場合の幅
- 本文（`メインコンテンツ`・`main`）の左端と、枠線と余白を除いた幅
- 絞り込み（年・月・分類・属性名）と「追加」の幅・左端と、行の並び（どれが同じ行にあるか、上から何行目か）
- 表の見出しの行が見えるか、行がスマートフォン用の並びか（Figma は行の部品の `幅=スマートフォン`、コードは表の最小幅が 0 か）

照合の許容は 1px。

## 照合のしかた

- アプリで再現する状態：読み込み中は、移動のリクエスト（RSC）を 3 秒遅らせて移動中の枠を出す。編集は一覧の最初の行の「編集」から開く。メニューを開いた状態・サイドメニューを隠した状態は「メニュー」を押す。下までスクロールした状態は一番下までスクロールし、画面に見えている絞り込みだけを比べる。
- 再現できない状態はテストを飛ばし、理由を出す。エラー（`（エラー）`）は、バックエンドの失敗をテストから起こせないため飛ばす（40 画面）。
- 削除確認・保存後・並べ替え中などは、ダイアログやトーストを除いた画面の寸法が一覧と同じなので、一覧を開いて照合する。

## Figma を変えたとき

1. `../scripts/export-figma-screens.js` の中身の後ろに `return await exportFigmaScreens("画面 / 支出");` のようにページの名前を付けて、ページごとに Figma で実行する（Figma の MCP の use_figma など）。
2. 返ってきた配列をまとめて `{ "fileKey": "…", "screens": [...] }` にし、`figma-screens.json` に保存する。
3. `APP_URL=… playwright test --project=app e2e/app/design-screens.spec.ts` で照合する。ずれたら、Figma とコードのどちらが正しいかを決めて直す。
